## 合约语义与产品规则

权威：`docs/reference/jnsvote/jns_vote.sol`。

| 方法 | 合约实际要求 | 本入口规则 |
| --- | --- | --- |
| 修改 | 当前区块小于传入的新开始区块 | 原开始区块和新开始区块都必须晚于当前区块 |
| 禁用 | 当前区块小于链上保存的开始区块 | 同左，且只接受未禁用状态 |
| 重新启用 | 当前区块小于链上保存的开始区块 | 同左，且只接受已禁用状态 |

不能把“已开始后永远不能修改”当作现有合约事实。当前前端采取更严格规则，但没有修改合约，也无法强制其他入口遵守这项前端策略。

## 双层校验

1. 表单加载提案并回显四个字段；提交前再次读取 `_proposals(id)` 与最新区块。开始或状态不符时禁用操作并阻断提交。
2. 数据层独立复核：提交、确认与显式执行都检查时间与提案状态，不能绕过表单直接调用。
3. 确认可能自动执行，必须与执行使用相同前置条件。
4. 修改还校验新开始/结束区块及标题；开始前快照被其他操作改变时，表单要求重新加载，避免无意覆盖。

## 保留与扩展防御

- 四类选择器均由合约接口派生；严格解码并保留完整调用数据。
- 仅接受指定投票合约目标、零原生金额、未执行且属于支持类型的交易。
- 表单显示类型、提案编号、标题、链接、区块与完整数据；确认/执行绑定已审阅数据。
- 多签数量、编号、详情和确认记录固定同一区块；编号按数量截断，保留0，不按值过滤。
- 提案状态按编号去重查询；状态未知时不允许操作。
- 非签名人不显示治理入口；断连或账户变化作废旧请求。
- 写入防重入；回执超时保留当前页面的广播哈希并阻止重复提交，可查询回执恢复。
- 外层成功但内部执行失败不报告治理操作成功。

## 边界

最新区块指签名前的读取时点，不能保证签名等待和入块期间没有跨越开始区块。应留足确认时间；若需要协议层绝对禁止已开始提案被修改，需要另行修改合约，前端无法替代。

广播锁限当前页面实例，不是跨刷新、跨标签页的全局交易管理器。请保留哈希，回执不明时不要关闭页面后重复提交。

验证门禁：`npm test`、`npm run build`。新增测试覆盖表单和数据层边界、四类编码标签及非签名人隐藏。双主题浏览器验证使用真实面板和模拟链/钱包依赖；不等同于主网签名验收。
